# Інструкція з прошивки COM-Box Vision -> Deye

Цей документ описує прошивку standalone-версії COM-Box без використання заводського bootloader.

> [!CAUTION]
> Заводський bootloader уже не використовується. Нова прошивка займає Flash від `0x08000000`. Перед прошивкою обов'язково збережіть повний backup для відновлення.

> [!WARNING]
> Проект перевірено збіркою PlatformIO. BMS використовує заводський `USART1` (`PA9`/`PA10`) на 9600 бод; значення `BRR` обчислюється з фактичної частоти APB2 під час запуску. CAN налаштовано на 500 кбіт/с (`BTR = 0x013A0003`) за умови APB1 = 32 МГц. Перед роботою на реальній платі перевірте обидва інтерфейси аналізатором.

---

## 🛠 Крок 1. Створення резервної копії (ОБОВ'ЯЗКОВО)

Перед першою прошивкою необхідно зробити повний бекап мікроконтролера за допомогою програматора ST-Link.

1. Завантажте та встановіть офіційну утиліту **STM32CubeProgrammer** (або ST-Link Utility).
2. Підключіть плату COM-Box до комп'ютера через програматор ST-Link (піни: `GND`, `SWCLK`, `SWDIO`, `3.3V`).
3. Запустіть STM32CubeProgrammer та натисніть кнопку **Connect**.
4. Зліва в меню перейдіть до розділу **Memory & File editing** (іконка пам'яті).
5. Налаштуйте параметри зчитування:
   - **Address**: `0x08000000` (стандартна адреса початку флеш-пам'яті).
   - **Size**: `0x40000` (для 256 КБ, щоб зчитати всю пам'ять цілком).
6. Натисніть кнопку **Read** і дочекайтеся завершення операції.
7. Біля кнопки "Read" натисніть стрілочку вниз, виберіть **Save As...** і збережіть файл під назвою `original_backup.bin`.

> [!TIP]
> Якщо щось піде не так під час розробки, ви завжди зможете прошити цей `original_backup.bin` назад (за адресою `0x08000000`), повернувши пристрій до заводського стану.

## 🚀 Крок 2. Прошивка через PlatformIO (Рекомендовано)

У цьому проекті конфігурація `platformio.ini` вже налаштована на безпечну прошивку.

```ini
; Частина platformio.ini, яка відповідає за безпеку:
upload_protocol = stlink
board_upload.offset_address = 0x08000000
board_build.ldscript = GD32F305RC_COMBOX.ld
```

Процес прошивки максимально простий:
1. Відкрийте цей проект у VS Code / PlatformIO.
2. Підключіть ST-Link до плати і комп'ютера.
3. На панелі PlatformIO (або внизу в статус-барі) натисніть кнопку **Upload** (іконка стрілочки "вправо").
4. PlatformIO автоматично скомпілює код і завантажить standalone-образ від адреси `0x08000000`.

## 🔧 Крок 3. Прошивка вручну (STM32CubeProgrammer)

Готові скомпільовані файли автоматично копіюються в папку `compiled_firmware/` у корені проєкту (також вони доступні в `.pio/build/genericGD32F305/`).

Перевірений результат актуальної збірки:
- `firmware.bin`: 15 296 байт;
- `firmware.hex`: містить ті самі дані з абсолютними адресами;
- діапазон образу починається з `0x08000000`;
- standalone-прошивка містить vector table на початку Flash.

### Варіант A: `firmware.bin`

Файл BIN не містить адрес. Якщо потрібно прошити вже скомпільований `firmware.bin` вручну, дотримуйтесь цих правил:

1. Підключіться до мікроконтролера в STM32CubeProgrammer.
2. Перейдіть у розділ **Erasing & Programming** (іконка стрілочки до мікросхеми).
3. Виберіть файл `firmware.bin` через кнопку **Browse**.
4. У полі **Start address** обов'язково вкажіть **`0x08000000`**.
5. Повне стирання дозволене тільки після перевірки резервної копії `combobox_bkp_40000.bin`.
6. Натисніть **Start Programming**.

### Варіант B: `firmware.hex`

Файл HEX уже містить абсолютні адреси від `0x08000000`, тому окремо вказувати адресу не потрібно. Виберіть `firmware.hex` у STM32CubeProgrammer.

Для автоматичної генерації BIN і HEX достатньо виконати збірку в PlatformIO (кнопка Build або `pio run`). Після цього файли автоматично скопіюються в папку `compiled_firmware/`.

## 📝 Крок 4. Перевірка після прошивки, індикація LED та підключення

| :--- | :--- | :--- | :--- | :--- |
| **`LED3`** | **Running** | `PB0` | **Рівномірно блимає** (1 сек світить / 1 сек пауза) | **Heartbeat процесора:** мікроконтролер живий, прошивка працює штатно. |

### 2. Підключення роз'ємів та портів

#### Вхід BMS RS485 (до батареї Vision V-LFP48100)
* **Апаратні піни MCU:** `PA9` (TX), `PA10` (RX).
* **Параметри зв'язку:** 9600 бод, 8N1, протокол Modbus RTU.
* **Адреса опитування:** `0x10` (заводська адреса Vision Pack16, підтверджена `BMS_TOOLS`).
* **Напрямок прийом/передача:** керується автоматично апаратною схемою плати від лінії TX (пин `PA1` не використовується).
* *Підказка:* якщо `LED4` не спалахує — поміняйте місцями лінії `A` та `B` на роз'ємі RS485.

#### Вихід PCS CAN (до інвертора Deye)
* **Апаратні піни MCU:** `PB8` (RX), `PB9` (TX) через частковий ремап (`Partial Remap`).
* **Параметри зв'язку:** 500 кбіт/с, трансивер ISO1050 (лінії `CANH` / `CANL`).
* **Розпіновка кабелю до Deye (порт BMS RJ45 на інверторі):**
  * Пін 4: `CANH`
  * Пін 5: `CANL`
* **Налаштування в меню інвертора Deye:**
  * Меню: `Battery Setting` -> `Batt Mode` -> вибрати `Lithium`.
  * Протокол літієвої батареї: вибрати `00` (Pylontech).
  * На екрані Deye мають з'явитися показники заряду (SOC %), напруги батареї та струмові ліміти.

#### Службові лінії та DIP-перемикач
* **`PC3` та `PC4`:** прошивка автоматично утримує `PC3 = LOW` та `PC4 = HIGH` (заводські рівні керування живленням/трансиверами).
* **DIP 1..4 (`PB12`..`PB15`):** за замовчуванням усі перемикачі встановлені у положення `OFF` (код `0`), що відповідає комунікаційній адресі батареї `0x10`.

### 3. Діагностика несправностей (Troubleshooting)

1. **`LED3` (Running) не блимає взагалі:**
   - Перевірте напругу живлення 3.3V та 5V на платі.
   - Переконайтеся, що прошивка була зашита з початкової адреси `0x08000000`.
2. **`LED3` блимає, але `LED4` (BMS-485) не подає ознак життя:**
   - Батарея не відповідає на запити `10 03 00 00 00 27 06 91`.
   - Перевірте, чи увімкнено живлення BMS на акумуляторі.
   - Поміняйте місцями дроти `RS485-A` та `RS485-B`.
   - Перевірте надійність контакту в клемній колодці.
3. **`LED3` та `LED4` блимають, але на інверторі Deye висить помилка зв'язку (`BMS Comm Fault` / `F56` / `W58`):**
   - Перевірте правильність обтискання витої пари CAN: `CANH` (пін 4) та `CANL` (пін 5) на роз'ємі RJ45 Deye.
   - Переконайтеся, що в інверторі обрано протокол `00` (Pylontech).
   - Перевірте наявність термінатора 120 Ом між лініями `CANH` та `CANL` (зазвичай вбудований у трансивер або інвертор).
