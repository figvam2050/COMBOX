# Інструкція з прошивки COM-Box Vision -> Deye

Цей документ описує безпечний процес прошивки плати Felicity COM-Box, щоб не пошкодити оригінальний завантажувач (bootloader).

> [!CAUTION]
> Заводський завантажувач Felicity знаходиться на початку флеш-пам'яті (до адреси `0x08004000`). Повне стирання чіпа (Mass Erase / Full Chip Erase) **знищить його**, і плата може перестати працювати у штатному режимі. Прошивати потрібно **тільки починаючи зі зміщення `0x08004000`**.

> [!WARNING]
> Проект перевірено збіркою PlatformIO. UART налаштовано на APB1 = 32 МГц (`BRR = 0xD05` для 9600 бод), CAN на 500 кбіт/с (`BTR = 0x013A0003`). Це розрахунок для поточної конфігурації сумісного STM32F1 framework; перед роботою на реальній платі перевірте тактову частоту та CAN аналізатором.

---

## 🛠 Крок 1. Створення резервної копії (ОБОВ'ЯЗКОВО)

Перед першою прошивкою необхідно зробити повний бекап мікроконтролера за допомогою програматора ST-Link.

1. Завантажте та встановіть офіційну утиліту **STM32CubeProgrammer** (або ST-Link Utility).
2. Підключіть плату COM-Box до комп'ютера через програматор ST-Link (піни: `GND`, `SWCLK`, `SWDIO`, `3.3V`).
3. Запустіть STM32CubeProgrammer та натисніть кнопку **Connect**.
4. Зліва в меню перейдіть до розділу **Memory & File editing** (іконка пам'яті).
5. Налаштуйте параметри зчитування:
   - **Address**: `0x08000000` (стандартна адреса початку флеш-пам'яті).
   - **Size**: `0x40000` (для 256 КБ, щоб зчитати всю пам'ять цілком).
6. Натисніть кнопку **Read** і дочекайтеся завершення операції.
7. Біля кнопки "Read" натисніть стрілочку вниз, виберіть **Save As...** і збережіть файл під назвою `original_backup.bin`.

> [!TIP]
> Якщо щось піде не так під час розробки, ви завжди зможете прошити цей `original_backup.bin` назад (за адресою `0x08000000`), повернувши пристрій до заводського стану.

## 🚀 Крок 2. Прошивка через PlatformIO (Рекомендовано)

У цьому проекті конфігурація `platformio.ini` вже налаштована на безпечну прошивку.

```ini
; Частина platformio.ini, яка відповідає за безпеку:
upload_protocol = stlink
board_upload.offset_address = 0x08004000
board_build.ldscript = GD32F305RC_COMBOX.ld
```

Процес прошивки максимально простий:
1. Відкрийте цей проект у VS Code / PlatformIO.
2. Підключіть ST-Link до плати і комп'ютера.
3. На панелі PlatformIO (або внизу в статус-барі) натисніть кнопку **Upload** (іконка стрілочки "вправо").
4. PlatformIO автоматично скомпілює код і завантажить його в мікроконтролер, починаючи з адреси `0x08004000`. При цьому сектори завантажувача залишаться недоторканими.

## 🔧 Крок 3. Прошивка вручну (STM32CubeProgrammer)

Готові скомпільовані файли автоматично копіюються в папку `compiled_firmware/` у корені проєкту (також вони доступні в `.pio/build/genericGD32F305/`).

Перевірений результат останньої збірки:
- `firmware.bin`: 15 204 байти;
- `firmware.hex`: містить ті самі 15 204 байти даних;
- діапазон адрес застосунку: `0x08004000..0x08007B63`;
- заводський bootloader у `0x08000000..0x08003FFF` до цих файлів не входить.

### Варіант A: `firmware.bin`

Файл BIN не містить адрес. Якщо потрібно прошити вже скомпільований `firmware.bin` вручну, дотримуйтесь цих правил:

1. Підключіться до мікроконтролера в STM32CubeProgrammer.
2. Перейдіть у розділ **Erasing & Programming** (іконка стрілочки до мікросхеми).
3. Виберіть файл `firmware.bin` через кнопку **Browse**.
4. У полі **Start address** обов'язково вкажіть **`0x08004000`**.
5. У розділі "Erase mode" виберіть варіант **Sector Erase** або переконайтеся, що опція встановлена так, щоб не стирати весь чіп (тільки "Skip erase" або стирання потрібних секторів). **НІКОЛИ не натискайте "Full chip erase".**
6. Натисніть **Start Programming**.

### Варіант B: `firmware.hex`

Файл HEX уже містить абсолютні адреси, тому окремо вказувати `0x08004000` не потрібно. Виберіть `firmware.hex` у STM32CubeProgrammer і переконайтеся, що режим стирання не виконує `Full chip erase`. Має стиратися лише область, яку займає HEX-файл.

Для автоматичної генерації BIN і HEX достатньо виконати збірку в PlatformIO (кнопка Build). Після цього файли автоматично скопіюються в папку `compiled_firmware/`; копіювання виконується після завершення генерації обох файлів.

## 📝 Перевірка після прошивки

Після успішної прошивки та перезавантаження пристрою:
- Перевірте світлодіоди: зазвичай світлодіод RUN повинен блимати (heartbeat).
- Якщо ви бачите мерехтіння діодів TX/RX на CAN або RS485, це означає, що пристрій надсилає/отримує дані згідно з алгоритмом.
