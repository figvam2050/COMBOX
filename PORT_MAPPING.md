> Усі налаштування прошивки та документація проекту повинні суворо відповідати цим фізичним даним.

Документ объединяет сведения из анализа заводской прошивки, проверки цепей на плате и текущей standalone-прошивки.

> Важно: обозначения периферии могут отличаться между STM32-совместимой документацией и GD32F30x SPL. В текущем GD32-коде BMS использует `USART0`, а CAN использует `CAN0`. В заводском анализе эти же физические интерфейсы обозначены как `USART1` и `CAN1`. Для подключения важны физические выводы MCU.

## Интерфейсы

### BMS RS485

| Параметр | Значение |
| --- | --- |
| Физические линии | `PA9` TX, `PA10` RX |
| Периферия в заводском анализе | `USART1` |
| Периферия в текущем GD32F30x SPL-коде | `USART0` |
| Скорость | `9600` бод |
| Формат | `8N1` |
| Протокол | Modbus RTU |
| Адрес по умолчанию | `0x01` |
| Управление направлением | Отдельный DE/RE GPIO не используется; направление должно переключаться схемой платы |

`PA9` одновременно является UART TX и линией, связанной с DI трансивера. Отдельную программную линию DE/RE для BMS назначать нельзя без дополнительной проверки схемы.

### PCS CAN / Deye

| Параметр | Значение |
| --- | --- |
| Физические линии | `PB8` RX, `PB9` TX |
| Периферия в заводском анализе | `CAN1` |
| Периферия в текущем GD32F30x SPL-коде | `CAN0` |
| Переназначение | CAN partial remap |
| Скорость | `500` кбит/с |
| Трансивер | ISO1050; отдельный DE/RE не нужен |
| Протокол | Pylontech-совместимые CAN-кадры для Deye |
| Используемые ID | `0x351`, `0x355`, `0x356`, `0x359`, `0x35C`, `0x35E` |

### PCS RS485

| Параметр | Значение |
| --- | --- |
| Физические линии | `PC12` TX, `PD2` RX |
| Периферия в заводском анализе | `UART5` |
| Прежнее обозначение в reverse engineering | `UART4` |
| Скорость | `9600` бод |
| Формат | `8N1` |
| Состояние | В текущей прошивке не инициализируется; используется CAN-канал |

## DIP-переключатель

Входы активны в нуле и имеют веса справа налево:

```text
address_value = (!PB15 * 8) + (!PB14 * 4) + (!PB13 * 2) + (!PB12 * 1)
```

| Переключатель | Порт | Вес | Состояние `ON` |
| --- | --- | --- | --- |
| DIP 1 | `PB12` | `1` | Логический `0` |
| DIP 2 | `PB13` | `2` | Логический `0` |
| DIP 3 | `PB14` | `4` | Логический `0` |
| DIP 4 | `PB15` | `8` | Логический `0` |

Заводская прошивка преобразует значение DIP `0` в коммуникационный адрес `0x10`.

## Не назначать без дополнительной проверки

- `PA1`: старая версия проекта ошибочно рассматривала его как RS485 DE/RE; заводской анализ это не подтверждает.
- `PC3` и `PC4`: известны только уровни `LOW` и `HIGH` при старте. Их электрическое назначение нужно проверить прозвонкой.
- `PC10` и `PC11`: обнаружены как возможный UART3, но физическое назначение разъема не подтверждено.
- `PD0` и `PD1`: CAN full remap; текущая схема использует partial remap на `PB8/PB9`.

## Источники и уровень подтверждения

- `FACTORY_PIN_ANALYSIS.md` - анализ заводского бинарника и фотографии платы.
- `src/main.cpp` - фактические настройки портов текущего firmware.
- Continuity-проверка платы - подтверждение `PA9/PA10` для BMS и `PB8/PB9` для CAN.

Перед подключением инвертора необходимо проверить осциллографом или логическим анализатором уровни, скорость, направление RS485 и CAN-терминацию.
